# Story 3.9: Use Semantic HTML Structure

Status: review

## Story

As an **assistive technology user**,
I want the page structure to be semantic without relying on CSS,
So that I can understand page hierarchy and purpose.

## Acceptance Criteria

1. **Heading hierarchy**: Every page has a single `<h1>` followed by `<h2>` / `<h3>` in correct nesting order — no skipped levels, no duplicated h1s
2. **Landmark elements**: Every page uses `<nav>`, `<main>`, and `<footer>` as native HTML elements — not `<div role="...">` substitutes
3. **Filter region**: The search-and-filter container in `section.html` uses `<section>` (not `<div role="region">`) for its landmark role
4. **Filter groups**: Filter checkboxes are grouped in `<fieldset>/<legend>` elements — not plain `<div>` containers
5. **Interactive elements**: All buttons use `<button>` (not `<div onclick>` or `<a>`); all comparison triggers are real `<button>` elements
6. **Comparison table**: `compare.html` uses a semantic `<table>` with `<caption>`, `<thead>`, `<tbody>`, and `scope` attributes on all `<th>` cells
7. **No empty headings**: No `<hN>` element renders with empty or whitespace-only text content
8. **No CSS-dependent structure**: Disabling CSS leaves all content readable in logical order; heading hierarchy and section purposes remain clear
9. **i18n completeness**: The `aria-label` on the filters section landmark uses `trans()` (not hardcoded English) so it renders in the correct language
